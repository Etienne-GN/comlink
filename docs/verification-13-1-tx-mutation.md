# Spec item 13.1 — tx-path message mutation: VERIFIED

pjproject: 2.17 (pinned submodule, built with -fPIC)
Harness: `core/tests/verify_tx_mutation.c` driven by
`tests/verify/verify-13-1.sh`

## The question

The design assumed that mutating a message inside a `pjsip_module`
tx callback, then calling `pjsip_tx_data_invalidate_msg`, puts the
modified message on the wire. The specific doubt was **in-dialog
requests generated by the dialog layer**, where behaviour could differ
from initial out-of-dialog requests. Nothing was built on top of this
until it was answered by a capture.

## Method

One pjsua instance calls its own address, which produces all three
message classes in a single process:

- `INVITE` — initial, out-of-dialog request
- `BYE` — in-dialog request, generated by the dialog layer
- `200 OK` — response

Module priority: `PJSIP_MOD_PRIORITY_TRANSPORT_LAYER`, chosen because
it sees messages last on the way out.

Evidence is `tcpdump` on `lo` filtered to the SIP port, read back with
`tshark` using per-class `sip contains` filters. Return codes were not
treated as evidence.

## Result

| Assertion | Count |
|---|---|
| INVITEs on the wire | 1 |
| INVITEs carrying the rule-injected header | 1 |
| INVITEs carrying the per-call ad-hoc header | 1 |
| INVITEs still carrying `User-Agent` (removed by rule) | 0 |
| BYEs on the wire | 1 |
| **BYEs carrying the rule-injected header** | **1** |
| 200 OKs on the wire | 2 |
| 200 OKs carrying the rule-injected header | 2 |

Rule hit counters: `probe-requests` 3 (INVITE, ACK, BYE),
`probe-responses` 3, `strip-ua` 1.

**Conclusion: the assumption holds for all three classes.** Injection
and removal both take effect, on initial requests, on dialog-generated
in-dialog requests, and on responses. The rule engine may be built on
this.

## Caveat on this capture

`RTP packets: 0` in the harness output is an artefact of the capture
filter (`udp port 5080`), which excludes the RTP ports. Media did go
active on both call legs. Asserting RTP flow requires a wider filter
and is the job of the loopback integration test, not this one.
